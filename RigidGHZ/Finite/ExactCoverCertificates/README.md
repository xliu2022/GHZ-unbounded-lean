# Exact-cover certificates for the supplementary seeds

The tables in `seeds.json` encode the explicit unrestricted examples in
Supplement S6 and the affine examples in Supplement S4. The unrestricted
vertices use the zero-based labels specified in the paper. An affine vertex
number `p*m+a` denotes the actual vertex `(p,a)` of `Fin 3 × ZMod m`.

`scripts/extract_exact_cover_seeds.py` extracts the printed S6 tables, expands
both two-layer constructions, and records the printed affine parameters.
The Lean data modules contain the resulting ordinary finite edge sets.

The distribution keeps the original CNF inputs and their clause metadata,
the pruned LRAT traces actually used in the proofs, and the required trace
chunks. Full unpruned solver traces and solver logs are regenerated by the
commands below. The discarded unnormalized proof candidates for A29, A31,
A41, and A47 are not required by the distributed proof or its default commands.

## Meaning of the CNF

There is one Boolean variable for every listed edge. Its interpretation is
membership of that edge in an arbitrary ordinary perfect matching `M`.

1. A positive clause requires at least one listed edge through each vertex.
2. A negative pair forbids two distinct edges sharing a vertex.
3. A negative clause for each prescribed matching excludes the possibility
   that all its edges belong to `M`.

`Finite/ExactCoverSAT.lean` proves that an ordinary perfect matching different
from every prescribed matching satisfies every such clause. The third step
uses the proved fact that one perfect matching cannot properly contain another
when all edges are nonempty. A refutation therefore proves ordinary
perfect-matching completeness. The validity checks also establish uniformity,
edge injectivity, the prescribed perfect matchings, their edge disjointness,
and their union being the complete host edge set.

For the larger affine cases, `Affine.normalize_counterexample` first translates
a counterexample so that its least present shift occurs at first coordinate
zero. The branch CNFs add one positive unit for that edge and negative units
for all edges of lower shifts. `ExactCoverNormalized.lean` interprets these
units as the actual membership and nonmembership facts supplied by the proved
normalization theorem. `A*Facts.lean` identifies the indexed tables with the
paper's affine formulas using ordinary kernel computation.

## Reproducing the certificates

Use the CaDiCaL executable bundled with the recorded Lean toolchain. From the
project root, the following commands reproduce the unnormalized inputs and
proofs; `--cases` can restrict the run to any listed seed.

```bash
python3 scripts/extract_exact_cover_seeds.py
python3 RigidGHZ/Finite/ExactCoverCertificates/reproduce.py generate
python3 RigidGHZ/Finite/ExactCoverCertificates/reproduce.py solve --cadical PATH_TO_CADICAL
python3 RigidGHZ/Finite/ExactCoverCertificates/reproduce.py prune
```

The four larger normalized families are reproduced by:

```bash
python3 RigidGHZ/Finite/ExactCoverCertificates/reproduce.py normalize \
  --cases A29 A31 A41 A47 --cadical PATH_TO_CADICAL
```

`lean-data`, `lean-facts`, and `lean-proof` regenerate the corresponding Lean
modules. For normalized families, `normalize` also emits the branch modules
and their combination via the normalization theorem. Each LRAT chunk contains
at most 1,000 learned clauses. Every physical Lean source file is comfortably
below the registry's 10,000-line limit.

The default `solve`, `prune`, and `lean-proof` actions skip the four normalized
families; the separate `normalize` command handles them. Some later chunks use
`SatLRATDirect.lean`: their LRAT input contains only the current 1,000 steps,
and each earlier premise is recovered from the type of its already checked
theorem. This has the same trust boundary as reconstruction from a full prefix.

`SHA256SUMS` records the seed table, certificate manifest, generator, original
inputs and clause metadata, pruned CNFs, retained LRAT traces, and any individual
trace chunks consumed by Lean. To regenerate it:

```bash
python3 RigidGHZ/Finite/ExactCoverCertificates/reproduce.py hashes \
  > RigidGHZ/Finite/ExactCoverCertificates/SHA256SUMS
```

The solver, generators, metadata readers, and LRAT parser are untrusted. The
importer reconstructs ordinary proof terms for each retained RUP inference;
the Lean kernel checks each generated declaration. The semantic assembler
checks each application of a proved semantic lemma against the exact literal
clause in that certified CNF. No native decision axiom, custom axiom, or
external solver assertion is admitted as a proof.

## Building and checking

After fetching the pinned Mathlib cache, run
`python3 scripts/build_finite_certificates.py` from the project root. It builds
the independent finite checks one at a time, so a fresh build does not schedule
all large kernel computations simultaneously. Completed modules are reused.

`Finite/Seeds/AxiomAudit.lean` traverses the actual proof dependencies of all
19 seed results and the five unrestricted maximum pair-codegree results. It
rejects any axiom other than `propext`, `Classical.choice`, and `Quot.sound`.
`Finite/Seeds/UnrestrictedDegrees.lean` assembles edge counts and exact maximum
pair-codegrees: U12, U15, U18, U21 have maximum pair-codegree 4, and U24 has 3.
These are properties of the same ordinary hypergraphs whose perfect matchings
are certified above. The small computations count their injectively indexed
edges through a proved equality with the ordinary host codegree.
